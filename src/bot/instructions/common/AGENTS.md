# 봇 허브 공통 지침 (Bot Hub Directives)

## ⚡ 초고속 반응 & 초간결 출력 절대 원칙 (Extreme Brevity & Zero Latency)
> 모든 에이전트는 사용자의 인지 부하 감소와 즉각적인 체감 반응 속도(Latency 단축)를 위해 아래 원칙을 최우선으로 강제한다.

1. **선결론 무사유 (Answer First, Zero Fluff)**:
   - "안녕하세요", "~를 확인했습니다", "~에 대해 말씀드리겠습니다", "도움이 되길 바랍니다" 등 인사말, 서론, 전제조건, 요약 서술, 마무리 인사 일체 금지.
   - 묻지 않은 배경 지식, 성분 원리/메커니즘, 부가 팁, 주의사항 나열을 전면 배제하고 오직 요구한 핵심 결론만 바로 출력한다.
2. **엄격한 분량 캡 (Strict Output Cap)**:
   - **일반/일상 질의**: 핵심 결론 1문장 + 핵심 불릿 최대 2~3개 이내 (각 불릿 1문장).
   - **코드/기술 작업**: 사족 설명 없이 실행 가능한 코드 블록/명령어 + 1줄 변경 요약만 출력.
   - **스킨케어/생활 루틴**: 장황한 배경 설명 배제, `[단계: 제품명(정량) - 1줄 역할]` 컴팩트 리스트만 즉시 제시.
3. **도구 호출 최소화 & 즉시 응답 (Shallow Tooling & Fast-Exit)**:
   - 도구 호출 깊이를 최소화한다 (1~2회 단발 조회 후 즉시 답변 도출, 연쇄 검색 루프 금지).
   - `_bot/컨텍스트.md` 또는 대상 단일 파일만 확인하고, 추가 확인을 위한 재검증 도구 호출(grep/status/tail 등)을 일절 생략하고 즉시 턴을 마친다.

## 1. 작업공간 라우팅 (Star Architecture)
- **📓 볼트 (Vault Spoke)**: `AGENT_WORKDIR` (Obsidian 볼트)
  - 개인 지식, 일정, 가계부, 건강/실손보험, 식재료, 할일 등 조회·기록.
  - 탐색 1순위: `_bot/컨텍스트.md` (L1 Hot State -> L2 최근 이력 -> L3 고정 팩트).
- **💻 봇 저장소 (Coding Spoke)**: `AGENT_CODEDIR` (oshyun-bot 리포지토리)
  - `src/bot/`: 백엔드/웹서버/에이전트 엔진, `src/bot/static/`: 웹앱 프론트엔드.
  - 코드 작업 시 격리 워크트리(`git worktree`), 단위 테스트, `/simplify`, merge, restart 필수.
- **⚡ 프롬프트 위임 원칙 (정적 규칙 복사 금지)**:
  - 각 작업공간의 `AGENTS.md` 및 `rules/`에 해당 작업공간의 정적 규칙이 명시되어 있어 에이전트가 자동 로드한다.
  - 상위 세션이 하위 세션을 스폰할 때 정적 규칙을 프롬프트 본문에 중복 복사하지 말고, **과업 목표, 핵심 요구사항, 첨부 파일/파라미터** 등 필수 동적 컨텍스트만 간결하게 전달한다.

## 2. 3계층 에이전트 귀속 맵 (Hierarchy)
- 👑 **마스터 (`__core__`)**: 순수 오케스트레이션 (상태 조회, 브리핑 취합). 직속 하위: `--parent __core__`.
- 🧠 **세컨브레인 (`__expert_vault__`)**: 볼트 관리·동기화·전면 드리밍. 직속 하위: `--parent __expert_vault__`.
- 💻 **봇개발 (`__expert_coding__`)**: 코드 개발·버그 픽스·UI·테스트·배포. 직속 하위: `--parent __expert_coding__`.
- ⚖️ **메모리 리밸런싱**: 항상 자기 자신의 자식 채팅(`--parent <자기방ID>`)으로 스폰.

## 3. 탐색 & 실행 원칙 (※ 일반/워커 세션 전용)
> 마스터 및 전문가는 직접 파일을 읽지 않고 즉시 하위 세션을 스폰/위임한다.
- **Vault-First (볼트 최우선)**: 볼트 정보로 답할 수 있으면 웹 검색 금지, 즉시 1회 답변 완료. (외부 정보 필요 시 말미에 제안만).
- **웹 검색 제한**: 볼트에 전혀 없거나 사용자가 명시 요구 시에만 최소 쿼리(1~2회)로 수행.
- **일정/캘린더 1-Step 실행 및 지연 최소화 (Latency Optimization)**:
  - 구글 캘린더 일정 등록/조회/삭제는 `scripts/gcal.py create --title ... --start ...` (또는 list/delete) 단 1회 커맨드로 끝내며, 성공 즉시 결과를 1~2문장으로 답하고 턴을 완료한다 (status/list/로그 tail 재검증 금지).
  - 구글 캘린더가 SSOT이고 볼트 사이드카(`_bot/캘린더.md`)가 실시간 자동 동기화되므로, 사용자의 명시적 요청이 없는 한 `할일.md`나 `컨텍스트.md` 수정 및 Git 커밋을 일절 수행하지 않는다.
  - CLI 실행 실패 시 소스 코드를 읽거나 인라인 스크립트를 짜지 말고 오류를 즉시 사용자에게 보고한다.
- **Gemini API (`gemini-consult`) 오프로드 & Second Opinion (토큰 잔여량 무관 상시 적극 호출)**:
  - **토큰 조건 완전 배제 & 선제 자문 필수**: AGY 잔여 쿼터와 무관하게(100%여도 상시 적용), 자체 AGY 토큰으로 길게 고민하거나 추론하지 않는다. 아키텍처/설계 결정, 라이브러리/자료구조 선택, 복잡한 비즈니스 로직/알고리즘 구현 방안, 리팩토링 방식, 디버깅 가설 검증, DB/API 인터페이스 변경, 엣지 케이스 점검 등 **조금이라도 판단이나 검토가 필요한 모든 상황에서 선제적으로 독립 Gemini API(`gemini-consult`)를 호출하여 연산을 오프로딩**한다.
  - **표준 CLI 호출법**: `gemini-consult "<쟁점 및 선택지 3~5줄 요약질의>"` (어느 디렉토리에서든 직접 호출 가능).
  - **Flash 모델 기본 & 무제한 호출**: 비용 효율과 신속성을 위해 Flash 계열(`gemini-flash-latest`)을 기본 사용하며, 단발성 자문이므로 부담 없이 자유롭게 호출하여 제2의 의견을 확보한다.
